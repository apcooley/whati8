# Multi-Food Confirmation UI — Implementation Task

**Project**: whati8 (existing Python FastAPI + Svelte nutrition tracker)
**Location**: /home/aaron/source/whati8/
**Date**: Feb 9, 2026

## Objective

Implement a multi-food confirmation UI that allows users to review, edit, and batch-submit multiple parsed food items before logging.

## Current State

- Conversational agent with 7 tools including `resolve_foods_nl` and `show_confirmation_form`
- Svelte 4 + Tailwind CSS frontend at `frontend/`
- FastAPI backend at `whati8/`
- Food search with fuzzy matching already exists
- Single-food confirmation flow exists but needs replacement

## Requirements

### Backend Changes

1. **Update `resolve_foods_nl` response** to include per-item:
   - `guessed_food` (best match)
   - `alternatives[]` (other possible matches, deduped)
   - `guessed_quantity`, `guessed_unit`
   - `confidence` score
   - `raw_text` (original user input)
   - `guessed_meal` (breakfast/lunch/dinner/snack based on time)

2. **Ensure `GET /foods/search`** works for direct DB fuzzy search (no AI)
   - Used for Edit → Search flow in form
   - No rate limiting needed

3. **Update `POST /logs` for batch submission**
   - Accept array of food logs
   - All-or-nothing: If any fails, roll back entire batch, return error
   - Return success or error message

### Frontend Components (Svelte)

Location: `frontend/src/lib/components/`

1. **MultiFoodForm.svelte** — Main container
   - Header: "Confirm Foods"
   - List of FoodRow components
   - MealSelector dropdown at bottom
   - "+" button for adding more foods
   - Footer: ❌ Cancel / ✔️ Log Foods
   - ✔️ grayed out if list empty
   - On submit: disable entire form + show spinner

2. **FoodRow.svelte** — Individual food row
   - Display: Food name (clickable) | Quantity (clickable) | ✏️ | 🗑️
   - Click food name → FoodSelector dropdown
   - Click quantity → QuantityEditor modal
   - ✏️ Edit → text input with ➕ Add food / 🔎 Search buttons
   - 🗑️ Delete → remove row
   - Zero match state: RED text + "(no match)"
   - Min 44px touch targets for mobile

3. **FoodSelector.svelte** — Alternatives dropdown
   - List of alternatives from resolve response
   - Each shows name + nutrient preview
   - "Other..." option → add-new-food dialog
   - Click outside → close and revert (no change)

4. **QuantityEditor.svelte** — Modal for quantity/unit
   - Unit dropdown (g, oz, cup, piece, fruit, slice, etc.)
   - Quantity number input
   - Live nutrition display: calories, protein, fat, fiber, weight(g)
   - Debounced calculation (no API call)
   - Save / Cancel buttons

5. **MealSelector.svelte** — Meal dropdown
   - Options: Breakfast / Lunch / Dinner / Snack
   - Pre-selected with agent's guess
   - "Add Meal" option disabled (future)

6. **InlineAddFood.svelte** — "+" add-more flow
   - Text input appears inline
   - On submit: calls resolve endpoint
   - Appends new FoodRow(s) to list
   - Spinner while resolving

### Agent Integration

1. Update `show_confirmation_form` tool to pass multi-food data
2. User edits happen client-side (no agent round-trips for edits)
3. Edit → 🔎 Search calls `/foods/search` directly (no AI)
4. Final submit → `POST /logs` batch
5. Success/error message returned to chat

### Loading States

- Row-level actions (🔎 Search): Inline spinner on that row only
- Add-more (+): Spinner in add area
- Final Submit (✔️): Disable entire form + spinner on button

### Edge Cases

- Empty list (all deleted) → gray out ✔️ submit
- Click outside dropdown → revert to previous selection
- DB error on submit → return error to chat, don't log anything
- Debounce quantity calculations (300ms)
- Mobile: sticky footer so submit buttons visible with keyboard
