## 1. Schema Changes

### New File: `whati8/schemas/multi_food.py`

```python
"""Schemas for multi-food confirmation UI."""
from pydantic import Field
from whati8.schemas.base import BaseORMModel


class MultiFoodConfirmationItem(BaseORMModel):
    """Flattened data for a single row in the Multi-Food Confirmation UI."""
    
    item_id: str = Field(..., description="Unique ID for frontend keying (UUID)")
    raw_text: str = Field(..., description="Original text snippet (e.g., '2 eggs')")
    parsed_quantity: float = Field(..., description="AI-parsed numeric quantity")
    parsed_unit: str = Field(..., description="AI-parsed measurement unit")
    confidence: float = Field(..., ge=0.0, le=1.0, description="AI confidence")
    
    # Selected match (default/guessed)
    selected_food_id: int | None = Field(None, description="DB ID of selected food")
    selected_name: str | None = Field(None, description="Name of selected food")
    serving_size: float | None = Field(None, description="Serving size of selected food")
    serving_unit: str | None = Field(None, description="Serving unit of selected food")
    calories: float | None = Field(None, description="Calories per serving")
    protein: float | None = Field(None, description="Protein (g) per serving")
    fat: float | None = Field(None, description="Fat (g) per serving")
    fiber: float | None = Field(None, description="Fiber (g) per serving")
    
    # Alternatives
    alternatives: list[dict] = Field(default_factory=list, description="Alternative matches")
    status: str = Field(..., description="matched|not_found|ambiguous")


class MultiFoodConfirmationResponse(BaseORMModel):
    """Response for multi-food confirmation form."""
    original_text: str = Field(..., description="Original user input")
    food_items: list[MultiFoodConfirmationItem] = Field(..., description="Parsed food items")
    guessed_meal: str | None = Field(None, description="AI-guessed meal (Breakfast/Lunch/Dinner/Snack)")
    overall_confidence: float = Field(..., ge=0.0, le=1.0)


class FoodLogBatchEntry(BaseORMModel):
    """Single entry for batch logging."""
    food_id: int = Field(..., description="Selected food ID")
    quantity: float = Field(..., gt=0, description="Quantity in grams")
    meal_id: int = Field(..., ge=1, le=4, description="Meal ID (1-4)")


class FoodLogBatchRequest(BaseORMModel):
    """Batch food log submission."""
    entries: list[FoodLogBatchEntry] = Field(..., min_length=1, description="Foods to log")
    logged_at: str | None = Field(None, description="ISO timestamp, defaults to now")
```

## 2. API Changes

### Update: `POST /foods/resolve` → returns `MultiFoodConfirmationResponse`

Modify `FoodResolverService` to:
1. Generate `item_id` (UUID) for each parsed item
2. Flatten the response structure
3. Include `guessed_meal` based on time of day
4. Apply deduplication rules (same food/different portion → dedupe)

### New: `POST /logs/batch`

```python
@router.post("/batch", response_model=dict)
async def create_logs_batch(
    request: FoodLogBatchRequest,
    db: AsyncSession = Depends(get_db),
    current_user: User = Depends(get_current_user),
):
    """Batch create food logs. All-or-nothing transaction."""
```

Behavior:
- All entries in single transaction
- On any failure → rollback all, return error
- On success → return `{"logged": len(entries), "message": "..."}`

### Existing: `GET /foods/search` 
Already exists, no changes needed. Used for Edit → 🔎 Search flow.

## 6. Data Flow

1. User types: "I had 2 eggs and toast"
2. Agent calls `resolve_foods_nl`
3. Backend returns `MultiFoodConfirmationResponse`
4. Agent triggers `show_confirmation_form` with `form_type: "multi_food_confirmation"`
5. Frontend renders `MultiFoodForm`
6. User edits (all client-side):
   - Change food selection → update local state
   - Edit quantity → QuantityEditor, update local state
   - Delete item → remove from local state
   - Add item (+) → call `/foods/resolve`, append to state
7. User clicks ✔️ Log Foods
8. Frontend calls `POST /logs/batch` with current state
9. On success → dismiss form, send confirmation to chat
10. On error → show error, keep form open
